Project checklist

Use the description to cover the points below, or explain them on your linked project page. Use headings in plain text. This checklist guides your submission; it does not automatically assess quality.

  1. User and problem: Who is it for, what task does it solve, and what benefit does it provide?
  2. How it works: Explain input, processing and output, and what your team built.
  3. Run instructions: State prerequisites, install/run/test steps and what a successful run looks like. A live public application is not required.
  4. Evidence: Show a genuine working example, expected versus actual results, sources and evaluation.
  5. Limitations: Include a failure case, known limitations, and relevant ethics/AI-use disclosure.

Choose a clear title and a short summary. If you provide a project website, use HTTPS and check its access. Do not post passwords, API keys or personal data. Add your HTTPS repository link in Repository URL. A missing link will be flagged for follow-up. Keep private repositories private; give the course team the required access through the course process.

YouTube: upload as Unlisted, allow embedding, wait for processing, check captions/audio and test signed out. Paste separate watch or youtu.be links for Presentation video and Demo video. Video length follows the final course announcement; this site does not impose a duration limit.
